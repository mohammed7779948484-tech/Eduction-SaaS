8. Professional Iterative Review Loop

Do not perform the task as a single implementation pass.

Use a structured quality loop for every major milestone.

Each milestone must follow this process:

Step A: Source Alignment

Before implementing the milestone:

* Re-read the relevant client-source sections.
* Re-read relevant Phase 1 sections.
* Re-inspect the relevant reference image area.
* Re-read the applicable project documentation.
* Record the milestone requirements.

Step B: Primary Implementation

The primary agent performs the implementation.

Subagents do not lead the initial implementation.

Step C: Primary Self-Review

The primary agent must review its own work before involving subagents.

Check:

* Source alignment.
* Technical correctness.
* Reuse.
* RTL.
* Responsive behavior.
* Accessibility.
* Visual quality.
* Documentation alignment.
* Missing states.
* Broken assumptions.

Fix obvious issues before requesting specialist reviews.

Step D: Specialist Reviews

Assign the milestone to the relevant subagents.

Each reviewer must inspect the actual implementation and provide evidence-based findings.

Do not ask every subagent to review every milestone.

Use only the relevant specialists.

Step E: Findings Consolidation

The primary agent consolidates findings into one ordered correction list.

Resolve duplicated or conflicting findings.

Prioritize in this order:

1. Blockers.
2. Critical issues.
3. Major issues.
4. Minor issues.
5. Suggestions.

Step F: Correction

The primary agent applies the accepted corrections.

Do not allow uncontrolled parallel edits.

Step G: Reverification

After corrections:

* Rerun technical checks.
* Rerun relevant visual checks.
* Reopen the affected source files.
* Confirm the correction did not introduce regressions.
* Update documentation.

Step H: Repeat

Repeat the review cycle until the milestone satisfies its completion gate.

A milestone is not complete while it contains:

* Any BLOCKER.
* Any CRITICAL.
* Any unresolved MAJOR.
* A conflict between implementation and authoritative source files.
* Broken lint, type, build, or runtime checks.
* A serious RTL or accessibility defect.
* A major visual defect at a required viewport.
* Documentation that contradicts the implementation.

Perform at least two meaningful review passes for:

* Source extraction and requirements.
* Dependency cleanup.
* DESIGN.md and tokens.
* /design-system.
* Homepage implementation.
* Final repository consistency.

Do not loop indefinitely over subjective preferences.

After the required quality gate is met:

* Document accepted minor issues.
* Document deferred suggestions.
* Proceed to the next milestone.
