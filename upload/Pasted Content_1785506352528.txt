6.5 Installation Retry Strategy

When installation fails:

1. Capture the exact error.
2. Retry with a longer timeout.
3. Retry using the supported package runner most compatible with the project.
4. Retry through the repository URL when package-style installation fails.
5. Use project-local installation.
6. Avoid creating a conflicting lockfile.
7. Verify network access to the source repository.
8. Check whether a proxy or environment restriction is causing the issue.
9. Retry individual skills rather than one large batch.
10. Avoid infinite retries.

Use a reasonable retry sequence with increasing delays.

Do not claim a skill is installed until all these are true:

* Its directory exists.
* Its SKILL.md is readable.
* Its metadata is valid.
* The active agent can discover it.
* Its required tools are available.
* You can explicitly invoke or apply it.

6.6 Honest Failure Handling

If a skill still cannot be installed after serious retries:

* Record every attempted command.
* Record the exact error.
* Record the retry count.
* Record whether the failure is network-related, permission-related, tool-related, or repository-related.
* Do not claim successful installation.
* Continue only when the active environment already provides equivalent built-in capability, and clearly document the substitution.

The goal is verified capability, not a false installation count.
