   622→8. Professional Iterative Review Loop
   623→
   624→Do not perform the task as a single implementation pass.
   625→
   626→Use a structured quality loop for every major milestone.
   627→
   628→Each milestone must follow this process:
   629→
   630→Step A: Source Alignment
   631→
   632→Before implementing the milestone:
   633→
   634→* Re-read the relevant client-source sections.
   635→* Re-read relevant Phase 1 sections.
   636→* Re-inspect the relevant reference image area.
   637→* Re-read the applicable project documentation.
   638→* Record the milestone requirements.
   639→
   640→Step B: Primary Implementation
   641→
   642→The primary agent performs the implementation.
   643→
   644→Subagents do not lead the initial implementation.
   645→
   646→Step C: Primary Self-Review
   647→
   648→The primary agent must review its own work before involving subagents.
   649→
   650→Check:
   651→
   652→* Source alignment.
   653→* Technical correctness.
   654→* Reuse.
   655→* RTL.
   656→* Responsive behavior.
   657→* Accessibility.
   658→* Visual quality.
   659→* Documentation alignment.
   660→* Missing states.
   661→* Broken assumptions.
   662→
   663→Fix obvious issues before requesting specialist reviews.
   664→
   665→Step D: Specialist Reviews
   666→
   667→Assign the milestone to the relevant subagents.
   668→
   669→Each reviewer must inspect the actual implementation and provide evidence-based findings.
   670→
   671→Do not ask every subagent to review every milestone.
   672→
   673→Use only the relevant specialists.
   674→
   675→Step E: Findings Consolidation
   676→
   677→The primary agent consolidates findings into one ordered correction list.
   678→
   679→Resolve duplicated or conflicting findings.
   680→
   681→Prioritize in this order:
   682→
   683→1. Blockers.
   684→2. Critical issues.
   685→3. Major issues.
   686→4. Minor issues.
   687→5. Suggestions.
   688→
   689→Step F: Correction
   690→
   691→The primary agent applies the accepted corrections.
   692→
   693→Do not allow uncontrolled parallel edits.
   694→
   695→Step G: Reverification
   696→
   697→After corrections:
   698→
   699→* Rerun technical checks.
   700→* Rerun relevant visual checks.
   701→* Reopen the affected source files.
   702→* Confirm the correction did not introduce regressions.
   703→* Update documentation.
   704→
   705→Step H: Repeat
   706→
   707→Repeat the review cycle until the milestone satisfies its completion gate.
   708→
   709→A milestone is not complete while it contains:
   710→
   711→* Any BLOCKER.
   712→* Any CRITICAL.
   713→* Any unresolved MAJOR.
   714→* A conflict between implementation and authoritative source files.
   715→* Broken lint, type, build, or runtime checks.
   716→* A serious RTL or accessibility defect.
   717→* A major visual defect at a required viewport.
   718→* Documentation that contradicts the implementation.
   719→
   720→Perform at least two meaningful review passes for:
   721→
   722→* Source extraction and requirements.
   723→* Dependency cleanup.
   724→* DESIGN.md and tokens.
   725→* /design-system.
   726→* Homepage implementation.
   727→* Final repository consistency.
   728→
   729→Do not loop indefinitely over subjective preferences.
   730→
   731→After the required quality gate is met:
   732→
   733→* Document accepted minor issues.
   734→* Document deferred suggestions.
   735→* Proceed to the next milestone.
